## Overview
This document outlines the design specification for **IronClaw**, an AI/Agentic productivity platform. The design system heavily leverages **Google Material 3 Expressive (M3X)** to create a premium, engaging, and emotionally resonant User Experience. 

Taking inspiration from Google AI Studio, Stitch, and Gemini Spark, this spec focuses on establishing trust, fluidity, and clarity during complex Agentic workflows. It implements physics-based spring animations, high-chroma dynamic colors, shape-morphing interactions, and flexible toolbars tailored to Agent chat, streaming, and tool management.

## Colors
IronClaw utilizes M3 Expressive's richer dynamic themes with higher chroma across all hues to create a vibrant, modern feel.
*   **Surfaces:** We rely on tonal nuanced surfaces (`surface-container-low` through `surface-container-high`) rather than heavy drop-shadows to separate chat history, reasoning blocks, and the background.
*   **Accents:** The `primary` color is a high-chroma violet/blue. 
*   **Hero Moments:** A dedicated `ai-spark` gradient/color is used exclusively for "Hero Moments" (e.g., when the Agent is actively generating or successfully completes a complex reasoning chain).

## Typography
Typography is grounded in variable fonts (`Roboto Flex` / `Google Sans`) to support M3X's emphasized styling.
*   **Emphasized Headlines:** Used for conversational greetings or empty states to create an emotional connection.
*   **Body Text:** Highly readable, optimized for long-form AI outputs. 
*   **Code & Tools:** `Roboto Mono` is used strictly for raw data, JSON payloads, and code block outputs generated by the Agent to clearly delineate structured data from conversational prose.

## Layout
The layout adapts M3X's fluid, adaptive container strategies.
*   **Flexible Toolbars:** The primary interface (Composer UI) acts as an adaptive floating toolbar that can dock to the bottom of the screen or float above content.
*   **Navigation Rails:** Used for the Configuration/Management UI. The rail features M3X expandable states, where icons move from above the label to in front of the label upon expansion to maximize screen real estate.
*   **Agent Chat Layout:** Follows an asymmetrical conversational flow, but Agent outputs occupy a wider, borderless structure to accommodate Markdown, tables, and nested activity cards.

## Elevation & Depth
Elevation is primarily expressed through tonal color shifts.
*   **Flat by Default:** Chat bubbles and activity cards are flat, utilizing `surface-container` variations to establish depth.
*   **Shadows for Floating Elements:** Soft, alpha-blended shadows are reserved exclusively for the Composer Toolbar, FAB (Floating Action Buttons), and FAB Menus to ensure they boldly overlap the scrolling chat history.

## Shapes
M3 Expressive introduces 35 new iconic shapes, which IronClaw utilizes to communicate AI states and interactivity.
*   **Shape Morphing:** Interactive elements, such as the submit/stop buttons, morph from a circle to a square upon press using the `shapes` modifier. 
*   **Scalloped Edges:** Used for M3X Loading Indicators. When an Agent is executing a backend tool (e.g., searching the web or executing code), a scalloped/starry shape is displayed to indicate "thinking".
*   **Chat Bubbles:** User inputs feature extreme border-radii (`24px`) with a sharp tail (`4px`), while Agent responses are clean and container-less.

## Components

### Composer UI
The Composer UI is the primary input mechanism. It utilizes the M3X **Toolbar** pattern rather than a static text area. 
*   It floats above the chat or docks to the bottom edge.
*   It includes an M3X **FAB Menu (Speed Dial)** on the leading edge. When tapped, it unfurls using spring physics to reveal tools (Add Context, Upload Image, Connect Integration).
*   The trailing edge contains an Icon Button for submission that morphs its shape on press.

### Agent Chat UI
The core interface where humans and Agents interact.
*   **User Bubbles:** Contained, tonal bubbles with distinct boundaries.
*   **Agent Responses:** Rendered as rich Markdown.
*   **Button Groups:** Action buttons (Regenerate, Copy, Edit) at the bottom of an Agent's response utilize M3X **Connected Button Groups**, which join buttons together and invoke shape-morphing animations when a segment is selected.

### Agentic Activity & Streaming UI
How the UI communicates that the Agent is "working".
*   **Branded Progress Indicators:** Replaces the standard linear loading bar. When text is streaming or the Agent is processing a complex prompt, a custom **Branded Progress Indicator** provides a fluid, organic, and "alive" feeling.
*   **Expandable Reasoning Blocks:** When an Agent uses a tool (e.g., "Searching the web..."), it appears as a small `surface-container-low` chip that can be expanded to view the raw logs.

### Configuration & Management UI
Where users configure agents, APIs, and settings.
*   Utilizes the M3X **Navigation Rail**.
*   **Split Buttons:** Used in settings tables to offer a primary action (e.g., "Deploy Agent") alongside a dropdown for secondary actions (e.g., "Deploy to Sandbox").

## Do's and Don'ts

*   **DO** use the Branded Progress Indicator for AI generation tasks to make the interface feel alive and intelligent.
*   **DON'T** use the high-chroma `ai-spark` color for static UI elements like standard buttons or links; reserve it for active Agentic streaming or Hero Moments.
*   **DO** implement spring physics (`spring-default`, `spring-fast`) for un-furling the FAB Menu and expanding reasoning blocks. Avoid hard-coded linear easings.
*   **DON'T** clutter the Chat UI with heavy drop shadows. Rely strictly on tonal surface shifts (`surface-container`) to separate Agent tool-use blocks from conversational text.
*   **DO** use shape morphing on icon buttons (like "Stop Generation") to provide satisfying, tactile visual feedback upon user interaction.

# IronClaw implementation & governance (appendix)

> This appendix is **IronClaw-specific governance**. The spec above is the
> source of truth for the design *language* (the M3 Expressive look, feel, and
> interaction intent). This appendix records *how* that language is realized in
> the IronClaw WebUI, and what still has to be resolved before a reskin.

## Precedence

- **DESIGN.md governs look & feel** — what the UI should look like, how it
  should feel, how interactions should behave.
- **The design-system epics govern implementation** — the design language is
  realized **natively** in IronClaw's React 19 + Tailwind v4 primitives. We do
  **not** adopt Material Web (`<md-filled-button>`, `<md-elevation>`, Lit web
  components); "M3 Expressive" here means the *visual/interaction system*,
  applied with our own components.
- The `data-theme` + `--v2-*` **token architecture is kept**. The reskin changes
  token *values* and adds new tokens; it does not replace the mechanism.

When these two ever appear to conflict, split the decision: DESIGN.md wins on
*what it looks/feels like*, the epic wins on *what we build it with*.

## Stack corrections (vs. generic Material-Web instructions)

- **No `tailwind.config.ts` / `theme.css`.** Tailwind v4 is CSS-first — tokens
  live in `src/styles/app.css` under `@theme` and
  `:root[data-theme="dark"]` / `:root[data-theme="light"]`.
- **Components are React + Tailwind**, styled via `--v2-*` CSS variables and the
  `cn()` helper (`src/utils/cn.ts`), across `src/design-system/`,
  `src/components/`, `src/layout/`, and `src/pages/`. Never `<md-*>` web
  components.
- **Motion policy.** `app.css` ships a deliberate static-motion policy — a
  universal `animation: none !important` rule, with a small, named set of
  sanctioned exceptions that each re-enable animation explicitly and are each
  suppressed again under `prefers-reduced-motion`. Verify the current set
  before adding to it:

  ```bash
  grep -n 'animation: none\|prefers-reduced-motion' src/styles/app.css
  ```

  Expressive motion (spring physics, shape-morph, speed-dial unfurl) is Phase-4
  work: opt-in, reduced-motion-gated, via an approved animation approach — not
  ad-hoc CSS keyframes that bypass the policy.

## Token inventory — what exists today

The `--v2-*` contract covers **colour**, plus a card shadow, the chat readable
width, and the select chevron. Regenerate the list rather than trusting this
paragraph:

```bash
grep -o '\-\-v2-[a-z0-9-]*' src/styles/app.css | sort -u
```

Measured on `main` at the time of writing: **31 tokens**, effectively all
colour. The non-colour axes — radius, spacing, motion, elevation, stacking
order, and a semantic type ramp — have **no token contract yet**; PR
[#7831](https://github.com/nearai/ironclaw/pull/7831) adds them at today's
computed values (a deliberate visual no-op) so that Phase 3 has somewhere to
change shape, density, elevation, and motion *from*. That matters because the
M3X target is mostly **not** colour: repainting only the colour tokens would
change the hue and leave the product looking as it does now.

## Open items to resolve before the Phase-3 reskin

1. **Dark palette** — derive dark values for **every** token. The supplied
   palette is light-only and the app is dark-default; derive per token by tonal
   shift, not literal inversion, and validate each pair in the `Tokens/Colors`
   story before adoption.
2. **Non-colour token axes** — radius, spacing, motion, elevation, stacking, and
   the type ramp. In flight as PR #7831; the reskin cannot set values for axes
   that have no tokens.
3. **Motion mechanism** — choose an animation approach (JS spring library vs.
   spring→bezier CSS approximations) and the `prefers-reduced-motion` strategy;
   none is installed today. Carried to Phase 4.
4. **Fonts** — vendor **Roboto Flex / Roboto Mono** (OFL) under `public/vendor/fonts`.
   **Google Sans is not freely redistributable** — pick a substitute (Roboto
   Flex for the emphasized-headline role) or confirm licensing before shipping.
5. **Contrast** — validate WCAG AA for all text/token pairings (e.g.
   `secondary #00E5FF` + `on-secondary #000`, `ai-spark` as text, `primary` on
   white). `ai-spark-dim` (`#FF4E9E33`) is an alpha glow, never text. The
   `Tokens/Colors` story should assert it so regressions fail the story suite.
6. **The `app.css` compat layer** — `!important` overrides remap raw palette
   classes (`bg-iron-*`, `border-white/10`, …) onto tokens at runtime. It is a
   shim the reskin has to unwind rather than restyle around; tracked in
   [#7890](https://github.com/nearai/ironclaw/issues/7890).
7. **Emitted-bundle verification** — the story and unit suites assert Tailwind
   class *strings*, not computed style, so a dropped `@theme` block can remove
   every generated utility with all gates green. A check over the emitted
   `dist/assets/*.css` belongs in the Phase-3 definition of done.

## Governance rules (enforced for agents)

See [`../../../../.claude/rules/design-system.md`](../../../../.claude/rules/design-system.md).
In short:

- **Source of truth:** this file + the Storybook catalog.
- **Token-driven:** no hardcoded hex or raw px in components — add tokens in
  `app.css` (light **and** dark), consume via `--v2-*`.
- **Story-per-component:** every primitive/composite/component with meaningful
  states has a colocated `*.stories.tsx`; changes are reviewed in Storybook and
  covered by `pnpm test:storybook`.
- **Accessibility bar:** WCAG AA contrast, preserved `aria-*`, keyboard/focus
  states, light + dark parity.
- **Native M3X:** no Material Web / `<md-*>` / parallel component framework.
