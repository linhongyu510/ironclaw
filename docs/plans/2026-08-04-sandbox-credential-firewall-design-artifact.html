□Profile on runs as uid=1000(sandbox) in /workspace.
□python3 runs an offline script and reads/writes files under the user's persistent workspace.
□Files persist across calls and container recreation.
□User B cannot observe User A; identical user IDs in different tenants remain isolated.

Per-user sandbox lifecycle

Containers are disposable execution state. The user workspace is the durable state and remains separate from every other user.

PR1 release boundary
Profile boot

The sandboxed deployment profile builds the process transport, sandbox backend, and reaper. Other profiles build none of them. Egress and credentials are later slices.

First user command

Derive hash(tenant,user), create that user's workspace directory, and look up containers by tenant and user labels.

Create or recover

If absent, create and start one non-root container with only that user's mount. If stopped, restart it. If its security-posture stamp is stale, recycle it.

Execute and reuse

Foreground commands for projects, threads, agents, and invocations owned by the same user reuse the container. Activity updates the per-user registry.

Idle protection

An active foreground invocation or incomplete process observation vetoes idle shutdown. Background/session process tracking is a later slice.

Stop, then remove

After the idle threshold the reaper stops the container. After stopped-container retention it removes the container while retaining the workspace.

Resume later

A later command restarts a retained container or creates a new one with the same {tenant,user} mount. Persistent files reappear; credentials do not.

Host shutdown or rollback

Graceful shutdown stops the reaper and sandbox runtime. Failed sandbox assembly returns an error; the sandbox profile never enables an unsandboxed fallback.

Follow-up PR4/PR5 · credential initialization → sandbox CLI use

This is the target credential contract, not an initial-launch requirement. The user may initiate setup directly, or an agent may request setup. In both cases the user supplies raw material only to the trusted host; the model and container receive an inert placeholder.

Core decision Ship the isolation primitive first. The profile gate, {tenant_id,user_id} ownership key, persistent workspace, lifecycle, and process port are shared across the directly reachable Docker daemon and the Docker daemon inside Railway's hosted sandbox VM. Firecracker and other new isolation substrates are out of scope. Egress and credentials attach through later host-owned ports without changing the sandbox identity contract.
